# Saving the student's work (design draft)

Confirmed brief, 2026-10-12. Not implemented yet.

## Why

margi's separation guarantee rests on git history, but many students don't know git. margi
therefore does the git mechanics itself, while the decision to save the student's work stays the
student's. margi never commits student work on its own: an automatic snapshot would remove the
human checkpoint and could record agent edits under the student's name.

## Who and what

A thesis student in Claude Code, mid-`/margi` run, who has never used git. Success: every margi run
grades a saved version the student approved, the student never types a git command, and the
history attributes correctly (saves are the student's and approved by them, records are the bot's).

Thesis: **what you saw is what gets saved.** The chat shows exactly which files will be saved;
`margi save --expect <hash>` is tied to that state and refuses if anything changed; Claude Code's
permission prompt is the consent.

## Setup (`margi init`, terminal, once)

- **git:** detect it. If missing, say "margi needs git to keep versions of your thesis" and offer
  `Install now? [Y/n]` where that works without admin rights (`xcode-select --install` on macOS,
  `winget install Git.Git` on Windows); elsewhere print the command for the student's platform and
  stop. No pure-Python fallback.
- `git init` silently if there is no repository.
- **Author:** ask for name and email, prefilled with the placeholders:

  > Your saved versions are recorded under a name.
  > Name [User]: ___
  > Email (optional): ___
  > You can change this later in thesis.config.yml, or ask your agent to do it.

  Enter keeps `User`. Without a terminal (agent, CI, tests) the placeholder is used without asking.
- Explain once that saves stay on this computer until a remote repository is added.
- Write `.gitignore` (`lit/` PDFs, build output).
- Write `.github/workflows/margi-guard.yml` only when a GitHub remote exists.

## Author identity

Stored only in `thesis.config.yml`; never written to git config:

```yaml
author:
  name: User
  email: null
```

`margi save` passes it to git for that commit only, so editing the file changes all later saves
(earlier saves keep their name). Three ways to set it: the init prompt, editing the file, or telling
the agent, which runs `uv run margi author --name "…" [--email "…"]` (on the `ask` list; the
`Edit(thesis.config.yml)` deny stays). margi output never echoes the name ("Saved as yours"). No
privacy claim beyond that.

## The save moment (only when a run needs it)

1. A `/margi` command finds unsaved changes outside `margi/` (today's preflight point) and pauses.
2. The agent shows margi's deterministic summary (never agent-written):

   > Your thesis has changes that aren't saved yet. margi only gives feedback on a saved version.
   > `chapters/2-method.typ` · +1,240 chars · `refs.bib` · +3 entries · `notes.md` · new file
   > Saving makes a version under your name (a git commit). It stays on this computer.

   With a remote, the last line reads "… (a git commit) and uploads it to github.com/…".
3. The agent runs `uv run margi save --expect <hash>`; `margi save` is on the **`ask`** permission
   list, so Claude Code shows its prompt. Approving is the consent.
4. Approved: "Saved as yours · 14:02 · 3 files" (with a remote: "· uploaded to github.com/…"),
   then the run continues.
5. Declined: the run stops. "Nothing was saved and no feedback was given. Run the command again
   when you're ready." margi never grades unsaved files.
6. Files changed since the summary: `save` refuses, the agent shows the summary again.
7. First save while the author is still `User`: the agent mentions once that the name can be set
   by telling it or by editing `thesis.config.yml`.

Commit message is fixed and generated by margi (`save: 3 files, +1,240 chars`) with a
`Margi-Save:` trailer. All or nothing: no file picking; to leave something out, decline.

## Remote

No remote: saves are local, and margi says so. With a remote, `save` pushes after committing (with
`GIT_TERMINAL_PROMPT=0`, so it never hangs on a password prompt); margi's own commits go up with
it. A failed push is not a failed save: "Saved on this computer; upload failed: <reason>. It will
go up with the next save."

## States and ranges

- First save in a fresh repo: setup files grouped as "margi setup (n files)".
- Many files: list up to 8, then "+ n more"; character change for text files, "changed" otherwise.
- Students who use git themselves never see the prompt; `margi save` equals committing.
- An existing `core.hooksPath` or foreign hooks: today's init error, in plain words.
- An "always allow" rule for `margi save` in `.claude/settings.local.json`: `status` warns, `init`
  removes it.
- Never shown: diffs of thesis text, git terms beyond the one mention, branches.

## Dashboard and status

- The dashboard is static and refreshed by runs, so it shows no unsaved-work indicator.
- Records name the version they graded: "graded the version saved 3 Oct, 14:02".
- Getting started: "plan committed" becomes "plan saved".
- `status`: time of the last save in one line.
- AI-use appendix: "12 of 15 versions were saved through margi, each approved in Claude Code's
  permission prompt."

## Anti-goals

No automatic snapshots, no reminders, no `/margi save` command, no agent-written text under the
student's name, no i18n (margi's own strings are English; the agent may speak the student's
language).

## Touches

`init.py` (git detection and install, author prompt, `.gitignore`, conditional workflow), new
`save` and `author` commands (reusing `guard.check_staged`), `config.py` (`author` defaults),
`templates/thesis.config.yml`, an `ask` list in `templates/claude-settings.json` and
`agent_settings.py`, preflight wording in `skills/margi/SKILL.md`, record captions and checklist
label in `templates/dash/dash.html`, `ai_report.py`, README and `docs/onboarding.md`.
